## 6. ALLOCATION LINEAGE & IMMUTABILITY

### The Immutability Invariant:
Once an optimization run completes and its manifest is signed, `data/processed/optimization/canonical_optimization_allocation.parquet` is **FROZEN IN PERPETUITY**. No UI, API endpoint, or administrative user may mutate rows or values in this artifact.

### Revision Branching:
In civil engineering practice, municipal site realities (e.g., underground utility lines, road widening, bridge construction) may necessitate field-level adjustments. CLIMORA handles this via the `AllocationRevision` ledger:

$$
\text{Effective Quantity}_{i,a} = \text{Optimized Quantity}_{i,a} + \sum_{k} \Delta \text{Revision}_{i,a,k}
$$

Every revision record preserves:
- `revision_id`: UUID4 unique identifier.
- `original_quantity`: The immutable optimization value.
- `proposed_quantity`: The modified engineering lot size.
- `revision_delta`: Difference ($\text{proposed} - \text{original}$).
- `revision_reason`: Mandatory civil/environmental justification.
- `author_identity`: Professional credentials and agency role of the modifier.
- `timestamp_utc`: Cryptographically sequenced timestamp.

The original optimization lineage remains 100% intact, and downstream reports explicitly present both the baseline modeled optimization and the field-adjusted plan.

## 11. PHYSICAL IMPLEMENTATION DEVIATION (F-27)

To mathematically audit field performance against model plans, Phase 1H introduces formulation **F-27**:

### Formulation F-27.1: Absolute Physical Deviation
$$\Delta Q_{i,a}^{\text{impl}} = Q_{i,a}^{\text{implemented}} - Q_{i,a}^{\text{planned}}$$

### Formulation F-27.2: Fractional Implementation Deviation Rate
$$\delta_{i,a}^{\text{impl}} = \begin{cases}
\frac{Q_{i,a}^{\text{implemented}} - Q_{i,a}^{\text{planned}}}{Q_{i,a}^{\text{planned}}} & \text{if } Q_{i,a}^{\text{planned}} > 0 \\
0.0 & \text{if } Q_{i,a}^{\text{planned}} = 0 \text{ and } Q_{i,a}^{\text{implemented}} = 0 \\
+\infty & \text{if } Q_{i,a}^{\text{planned}} = 0 \text{ and } Q_{i,a}^{\text{implemented}} > 0
\end{cases}$$

Divisions by zero are trapped and handled deterministically.

## 13. MRV QUALITY CONTROL ENGINE (F-28.1)

Empirical post-intervention observations cannot be utilized for impact measurement without passing the five-point CLIMORA MRV Quality Control Engine (**F-28.1**):

$$
\text{QC\_Pass} = \Phi_{\text{spatial}} \wedge \Phi_{\text{temporal}} \wedge \Phi_{\text{cloud}} \wedge \Phi_{\text{sensor}} \wedge \Phi_{\text{geo}}
$$

1. **Spatial Coverage Audit ($\Phi_{\text{spatial}}$):**
   Post-intervention observation must provide 100.0% spatial coverage over all treated H3 cells.
2. **Temporal Window Compatibility ($\Phi_{\text{temporal}}$):**
   Acquisition must match the canonical pre-monsoon baseline window: Preferred window Day of Year (DOY) $95 \le \text{DOY} \le 115$; Fallback window $90 \le \text{DOY} \le 120$ subject to maximum offset $\le 15$ days from canonical target DOY 105. DOY is the canonical representation; calendar dates derive dynamically from the acquisition year to preserve leap-year validity.
3. **Cloud & Shadow Masking ($\Phi_{\text{cloud}}$):**
   Source scene cloud/shadow contamination within the target AOI must not exceed $5.0\%$, with 100% of invalid/cloud/shadow pixels masked via QA bitmasks so that exactly 0.00% unmasked invalid pixels enter downstream metric computation.
4. **Sensor Radiometric Consistency ($\Phi_{\text{sensor}}$):**
   Sensor compatibility is metric-specific: Thermal LST verification requires thermal radiometers (Landsat-8/9 TIRS USGS Collection 2 Level-2 or Drone Thermal Radiometric). Sentinel-2 MSI provides optical bands (NDVI/NDBI) and CANNOT directly measure thermal LST; no cross-sensor thermal equivalence is implied.
5. **Geolocation Alignment ($\Phi_{\text{geo}}$):**
   Observation spatial reference system (UTM Zone 43N / WGS84) must align with the canonical analytical framework with native spatial resolution $\le 30.0\text{m}$. Sub-pixel coregistration ($\le 0.5$ pixels / $15.0\text{m}$) is a QC requirement pending executable validation on raw scene delivery.

If any audit predicate fails, the observation is flagged `QC_FAILED` with detailed diagnostic violation logs, blocking verification.

## 20. FORMULATION GOVERNANCE

Phase 1H formalizes three new operational and verification formulations:

### Ratified Formulations:
1. **F-27 (Implementation Physical Deviation):** Defines absolute physical lot deviation $\Delta Q_{i,a}^{\text{impl}}$ and fractional deviation rate $\delta_{i,a}^{\text{impl}}$ with zero-denominator safeguards.
